# 姿态解算：飞机怎么知道自己"歪没歪"

---

## 0. 先回答一个问题：飞机为什么要"知道自己歪没歪"

回想你的 PID 笔记：PID 的第一步是算误差

$$e(t) = \text{目标} - \text{当前}$$

四轴飞行时，目标姿态是遥控器给的（"保持水平"），但**"当前姿态"是多少？**没人告诉我们。

- 飞机往前倾了多少度？——没有任何一个传感器会直接报这个数。
- 如果连"当前歪没歪、歪了多少"都不知道，PID 就算出来了也没有"实际值"可减，成了无源之水。

所以姿态解算要干的事就一句话：**用传感器数据，把"飞机现在是什么姿态"算出来**。

它是 PID 的上游。先学会"知道自己歪没歪"，才能学"纠正歪"。

---

## 1. 飞机上有哪些传感器，各能告诉我们什么

| 传感器 | 测什么 | 打个比方 |
|---|---|---|
| 陀螺仪（MPU6050 的一半） | 转得**多快**（°/s） | 闭着眼转圈，能感觉转得快慢，但不知道转到哪了 |
| 加速度计（MPU6050 的另一半） | 受力 | 站在电梯里，能感觉电梯在加速还是减速 |
| 磁力计（HMC5883L） | 地磁场方向 | 指南针，知道机头朝哪（航向） |
| 气压计（MS5611） | 大气压 | 高度计，跟姿态没关系，这学期先不管它 |

注意关键词：陀螺仪给的是"**转多快**"，不是"转到哪"。就像车速表告诉你"每小时 60 公里"，但不告诉你"你在哪个城市"。

下面两节，我们先用最简单的思路各试一次，看看为什么单独用哪一个都不行。

---

## 2. 思路一：用加速度计直接算倾角

### 2.1 原理

静止的飞机只受一个力：**重力**。重力方向永远是"竖直向下"，这在地球上不会骗人。

加速度计测的就是受力。所以：

- 飞机水平放置 → 重力全在 z 轴上 → 读数 ≈ (0, 0, 1)（单位是 g）
- 飞机往前倾了 30° → 重力在加速度计的坐标系里就"歪"了 → 读数变成 ≈ (0.5, 0, 0.87)

换句话说：**加速度计读数指向的方向 = "下"的方向**。知道"下"在哪，自然就知道"歪"了多少。这就是用加速度计算倾角的原理：

$$roll = \tan^{-1}\left(\frac{a_y}{a_z}\right), \qquad pitch = \tan^{-1}\left(\frac{-a_x}{\sqrt{a_y^2 + a_z^2}}\right)$$

直觉理解：$a_y$ 是"侧向漏出来的分量"，$a_z$ 是"竖直的分量"，两个一对比就得到倾角。飞机歪得越厉害，侧向分量越大。

### 2.2 但是有两个毛病

1. **电机一转就抖**：电机带动桨叶狂震，加速度计读数抖成筛子，任何单次读数都没法信。
2. **一加速就骗人**：飞机加速或转弯时，受力 ≠ 重力（多出了惯性力）。
   - 类比：公交车突然加速，你身体会后仰——你那一刻"感觉到的下"是假的。加速度计也一样，飞机一加速，它报的"下"就是假的。

**结论：加速度计"长期看"很靠谱（重力永远朝下，平均值不会骗人），"每一瞬间"都不靠谱。**

## 3. 思路二：用陀螺仪积分

### 3.1 原理

陀螺仪告诉你转得有多快（角速度 $\omega$，单位 °/s）。如果我**知道此刻的角度**，那么过了 $\Delta t$ 秒后：

$$新角度 \approx 旧角度 + \omega \times \Delta t$$

每 1ms 算一次、累加一次，就能一直"追"着角度走。这个累加操作叫**积分**。

- 优点：**快、不骗人**。飞机怎么转，陀螺仪立刻知道，没有延迟；而且它只关心"转"，跟加速、受力都没关系，公交车加速骗不了它。
- 致命缺点：**会飘**。陀螺仪有"零偏"——明明静止不动，读数却不是精确的 0，而是 0.5、-0.3 这种小偏差。积分一次偏一点点，1 秒偏零点几度，十几秒就偏出好几度。而且这个零偏还随温度变化。

**结论：陀螺仪"短期"准得不得了，"长期"会飘到天边。**

## 4. 互补滤波：两个都不完美，但合起来完美

把前面两节并排看，是不是很妙：

| | 加速度计 | 陀螺仪 |
|---|---|---|
| 短期 | 脏（振动、加速欺骗） | **准** |
| 长期 | **准**（重力永远朝下） | 飘（零偏累积） |

一个短期不行、长期行；另一个短期行、长期不行。**正好互补**——这就是"互补滤波"名字的由来。

思路一句话：**平时信陀螺仪（它快），但每隔一会儿用加速度计"抽查纠偏"**：如果陀螺仪积分出来的角度和加速度计算出来的角度差远了，说明陀螺仪飘了，把它拽回来。

### 4.1 一维版本（必看，整个姿态解算的钥匙）

先假装飞机只有一个角度（比如 roll）。陀螺仪给角速度 $\omega$，加速度计算出参考角度 $\theta_{acc}$，我们维护融合角度 $\theta$。每步做三件事：

```
误差  e  = θ_acc − θ         ① 参考值说 20°，我积分出来 18°，差 2°
修正  ω' = ω + Kp × e       ② 把误差乘个系数加进角速度 → 相当于"用力拽"
更新  θ  = θ + ω' × Δt      ③ 还是积分，但每步都被拽回来一点
```

用图感受一下：陀螺仪积分是"惯性滑行"，加速度计是"路边的路标"。每走一步，都看一眼路标，发现自己走偏了 2°，就往回掰一点。滑行提供平滑性，路标保证不跑偏。

- **Kp 大**：拽得狠、纠偏快，但加速度计的抖动也跟着进来（角度抖）；
- **Kp 小**：更信任陀螺仪，曲线平滑，但纠偏慢，飘了要很久才拉回来。

（进阶：如果误差一直存在——比如陀螺仪有恒定零偏——光靠 Kp 拽总差一口气，这时再加一个积分项 Ki，把"持续的偏差"慢慢吃掉。学长代码里 Kp=2.0、Ki=0.005 就是干这个的。一维版先记住有 Ki 这回事即可，不用深究。）

> **配套演示**：[互补滤波演示.html](互补滤波演示.html) —— 直接看陀螺仪怎么飘、加速度计怎么抖、Kp/Ki 怎么把它拽回来，所有参数可拖。

### 4.2 升级到三维

一维里："角度差多少"是一个数（20° − 18° = 2°）。
三维里："方向差多少"是一个**向量**——实测的重力方向和预测的重力方向不重合，差的角度和差的方向，用**叉积**一步算出来。

不用怕叉积这个词，它就是个数学工具：**两个方向向量做叉积，得到一个新向量，它的方向 = 差的方向，大小 ≈ 差了多少度（小角度时）**。相当于一维里的那个"2°"，升级成了三维。

后面第 6 节你会看到，Mahony 滤波里到处是叉积——现在知道它只是"三维版的误差"就够了。

## 5. 三维姿态怎么表示：为什么用四元数

三维姿态 = "机体坐标系"相对"地面坐标系"转了多少。表示方法有三种，飞控圈最后几乎全用四元数。逐个看：

### 5.1 欧拉角（roll / pitch / yaw 三个角）

最直观，你脑子里想的"前倾 30°、右倾 10°、机头偏左 20°"就是它。**但有三个问题**：

1. **万向锁**：飞机机头朝上（pitch = 90°）时，roll 和 yaw 会"撞车"——两个旋转变成同一个方向，数学上炸掉。四轴飞行器俯仰到 90° 虽然不正常，但翻滚动作（学长的安全逻辑允许 ±65°）逼近它，不能赌。
2. **顺序敏感**：先转 roll 再转 pitch，和先转 pitch 再转 roll，结果不一样。三个角还得规定顺序，容易乱。
3. **更新慢**：用欧拉角做积分更新，每步都要算一堆三角函数，STM32 跑起来吃力。

### 5.2 旋转矩阵（3×3 九个数字）

直观，但九个数太笨重，更新麻烦，还要时刻保证矩阵"端正"（数学上叫正交），维护成本高。

### 5.3 四元数（4 个数字）

$$q = q_0 + q_1 i + q_2 j + q_3 k, \qquad q_0^2 + q_1^2 + q_2^2 + q_3^2 = 1$$

- 没有万向锁；
- 更新只需要 4 个数的加减乘（快，单片机轻松跑）；
- 只有一个约束：模长等于 1。

**怎么理解它**：别管它"超复数"的数学本质，就把它想成"一根旋转轴 + 绕这根轴转多少度"的压缩打包——4 个数一起描述了"机体相对地面转成什么样了"。你只需要记住：**姿态 = 4 个数 (q0,q1,q2,q3)，它们的平方和等于 1**。

虽然内部用四元数运算，但最后要**转回欧拉角**给 PID 用（PID 想要"角度"这个直观的量）。

## 6. Mahony 互补滤波：完整流程（学长 IMU.c 就是它）

学长 `IMU.c` 的 `Attitude_Update()` 就是第 4 节思想的三维实现（Mahony 互补滤波）。流程分八步，对照代码逐行看：

```
① 读传感器 → 原始值 → 单位换算
     陀螺仪 LSB → rad/s（学长用 RAW_TO_RAD = 0.0010653，对应 ±2000°/s 量程）
     加速度计不用换算单位（后面要归一化，见②）

② 加速度计向量归一化
     把 (ax,ay,az) 除以模长，变成"方向"而不是"大小"
     —— 我们要的是"重力朝哪"，不是"重力多大"

③ 用当前四元数 q，预测"重力应该指向哪"
     一个固定公式算出 (vx, vy, vz)：
     vx = 2(q1q3 - q0q2)
     vy = 2(q0q1 + q2q3)
     vz = q0² - q1² - q2² + q3²
     —— 如果姿态估计得对，这个预测方向应该和②的实测方向重合

④ 对比实测和预测：叉积 = 三维版的"误差 e"
     ex = ay·vz - az·vy
     ey = az·vx - ax·vz
     ez = ax·vy - ay·vx
     —— 方向 = 差的方向，大小 ≈ 差多少（对应一维版的 "θ_acc − θ = 2°"）

⑤ 误差过 PI，修正陀螺仪读数
     gx = gx + Kp·ex + exInt        (exInt += ex·Ki·halfT)
     —— 把"偏了 2°"折算成"角速度补偿量"，加回陀螺仪
     —— Kp 拽比例误差（=一维的 Kp），Ki 吃持续偏差（=零偏）

⑥ 用修正后的角速度更新四元数（4 行加法，别怕，就是 4 个数的累加）
     q0 = q0 + (-q1·gx - q2·gy - q3·gz)·halfT
     q1 = q1 + ( q0·gx + q2·gz - q3·gy)·halfT
     q2 = q2 + ( q0·gy - q1·gz + q3·gx)·halfT
     q3 = q3 + ( q0·gz + q1·gy - q2·gx)·halfT
     —— halfT 是采样周期的一半，见第 7 节

⑦ 四元数归一化（除以模长，防止越积越长而飘走）
     norm = 1/√(q0²+q1²+q2²+q3²)，四个数都乘上它

⑧ 四元数 → 欧拉角（3 个公式，给 PID 用）
     roll  = asin( 2(q0q2 - q1q3) ) × 57.3
     pitch = -atan2( 2(q0q1 + q2q3), q0²-q1²-q2²+q3² ) × 57.3
     yaw   = atan2( 2(q0q3 + q1q2), q0²+q1²-q2²-q3² ) × 57.3
```

> 磁力计在哪？绕竖直轴（yaw）转时，重力方向不变，加速度计帮不上忙。所以 yaw 的"参考"换成地磁场方向——第③④步把"预测重力"换成"预测磁场"，叉积照算。学长代码里磁力计部分就是干这个的（by/bz 那几行），本质同一个思想。

你会发现整个流程没有一处"聪明"的数学：**就是"预测 → 对比 → 拽回来 → 积分"，循环往复，每秒上千次**。这就是互补滤波的全部秘密。

> **配套演示**：[三维姿态解算演示.html](三维姿态解算演示.html) —— 白色线框是真实姿态、彩色方块是 Mahony 解算结果，看它们贴在一起；把零偏调大、把磁力计勾掉，看它怎么飘。

## 7. 你们工程里要做的事（结合你的 bsp.c 现状）

你的 `bsp.c` 已经把三个传感器的**原始数据**读通了，这是最耗时的部分，你已经完成。接下来在你自己工程里按顺序做：

### 7.1 传感器配置（量程和滤波）

- 陀螺仪配成 **±2000°/s**（寄存器 GYRO_CONFIG 的 FS_SEL=3），这样学长换算系数 `RAW_TO_RAD=0.0010653` 直接能用（131 LSB/°/s → 弧度/秒要乘的系数就是它）；
- 加速度计量程 ±2g 或 ±4g 都行（记得算灵敏度和 z 轴减 1g）；
- 配 DLPF 低通滤波（滤掉电机的高频振动，振动是姿态抖动的第一大来源）。

### 7.2 零偏校准（不校必飘）

上电静止，连续采 100 次取平均，把陀螺仪三轴偏移扣掉（学长 `MPU6050_Offset()` 的写法）。**不做这步，互补滤波里 Ki 就得替你背锅，角度会缓慢漂移。**

### 7.3 采样周期（你们现在太慢了）

- 姿态解算要 **1ms 级别**（学长是 1ms，PID 是 3ms）；
- 你现在的 SensorTask 是 50ms——太慢，积分一步误差就大，飞起来没法用；
- 做法：单独开一个高优先级姿态任务（1ms），或把 MPU6050 读取提到 5ms 以内；
- halfT（第 6 节第⑥步那个"周期一半"）**要实测**：你们已经初始化了 DWT 周期计数器，用它量真实循环时间，别拍脑袋写固定值。

### 7.4 坐标轴和符号（错一个全盘皆输）

拿板子手动转，用串口/上位机看：前倾时 pitch 是正是负？右倾时 roll 是正是负？机头左转时 yaw 怎么变？和学长 `docs/九轴数据变化.txt` 的记录对照。**符号反了，姿态解算出来的角度是反的，后面 PID 全乱。**

### 7.5 验证三步走（上 PID 之前必须全过）

1. **静止**：放平，看 roll/pitch 是否 ≈ 0，且不抖不飘；
2. **慢转**：手拿着慢慢转，看角度是否跟手（无滞后、无突变）；
3. **快晃**：快速晃动，看是否跟得上，但**不会因为振动乱跳**。

这三步过了，姿态解算才算真正"能用"，之后学的 PID 才有"实际角度"可减。

## 8. 常见坑清单（学长和你们都踩过）

- **四元数忘了归一化**（第⑦步漏了）→ 姿态越飘越远，无解；
- **单位搞错**：陀螺仪原始值直接当 rad/s 用（差 131 倍或 16.4 倍），角度全错——先换算再进公式；
- **HMC5883L 数据顺序**：它的寄存器顺序是 X、Z、Y，不是 X、Y、Z——你 bsp.c 里已经写对并注释了，千万别"优化"回去；
- **只信陀螺仪**（Kp=0）→ 飘；**Kp 太大** → 角度跟着振动抖；
- **加速度计不归一化**就去做叉积 → 误差大小和"受力大小"挂钩，姿态对错都说不清；
- **采样周期和实际循环周期不符** → 积分步长不对，等效于参数错乱；
- **在振动环境里调试**：先固定机架/拆桨再验证姿态，否则加速度计噪声会把你看晕。

## 9. 学习顺序建议

1. **把第 4 节的一维互补滤波看透**——拿纸笔把"误差→修正→更新"三步手推一遍，这是全部理论的钥匙；
2. **读学长 IMU.c 逐行**，每行标注它是第 6 节的第几步（①②③…），你会发现没有一行是"魔法"；
3. **移植到你的工程**，先不接 PID，只串口打印角度，按第 7 节验证三步走；
4. 姿态稳了，再回头看 PID——那时候你手里有"实际角度"这个反馈了，PID 笔记里的公式才有处安放。
